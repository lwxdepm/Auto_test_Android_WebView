## 新增完整业务闭环优先级建议
优先自动化以下闭环，因为它们是代码中真实跨模块业务链路，现有用例多为页面/原子操作：
- **CX-BIZ-AUTH-001**（P0）新用户首登到首轮对话：使用新手机号登录 → 勾选用户协议/隐私政策 → 跳转个人信息必填页 → 验证未填必填项不能保存 → 填昵称/生日/性别/当前关注 → 保存 → 进入 /chat → 展示首次激活欢迎语 → 发送一句普通问题。
- **CX-BIZ-CHAT-001**（P0）发送消息到历史恢复、反馈和分享：新建对话 → 发送短问题 → 等待 thinking/process/answer 完成 → 校验免责声明/复制按钮 → 点有帮助/没帮助 → 分享至此 → 打开分享链接 → 回到 App 打开侧栏历史 → 重新进入该会话 → 删除测试会话。
- **CX-BIZ-CHAT-002**（P1）中断、重试、编辑后重试：发送要求长回答的问题 → 停止生成 → 验证已中断 chip 和重试入口 → 点击重试 → 再次中断 → 编辑用户问题并保存重试。
- **CX-BIZ-COMM-001**（P0）聊天内生成沟通卡并保存到我的材料：新建对话 → 发送“帮我整理一张下周复诊给医生看的沟通卡，重点是腹泻和用药调整” → 等待 generate_communication_card 工具卡片出现 → 断言卡片含就诊目标/我的情况/特别说明/我的问题 → 点击“保存到我的材料” → 点击“查看材料”或进入 /materials → 打开该卡详情。
- **CX-BIZ-COMM-002**（P1）仅表达复诊意图时先询问再生成：发送“我下周复诊，不知道要问医生什么” → 观察 AI 先询问是否需要整理沟通卡，不直接出卡 → 回复“需要，帮我整理” → 再等待沟通卡出现。
- **CX-BIZ-COMM-003**（P1）同一工具结果重复保存幂等：基于聊天生成的沟通卡，快速点击保存或保存后刷新原会话再次渲染同一 toolCall → 再次尝试保存。
- **CX-BIZ-COMM-004**（P1）已保存沟通卡编辑后返回原会话并注入增量事件：从某 chat session 侧栏进入我的材料 → 打开沟通卡 → 编辑“我想问医生的问题”并保存 → 返回原会话 → 发送“刚才我改了沟通卡，帮我确认要问的问题”或调试接口查看 session-events。
- **CX-BIZ-COMM-005**（P1）读取已保存沟通卡并展示引用 chip：预置一张沟通卡 → 新会话发送“请查看我保存的最新复诊沟通卡并总结要点” → 等待模型调用 read_medical_documents({ids:["c-1"]}) → 查看 assistant 上方沟通卡引用 chip → 点击 chip。
- **CX-BIZ-COMM-006**（P2）重复用户消息不重复展示沟通卡：用户请求生成沟通卡并成功展示 → 立刻重复发送完全相同消息。
- **CX-BIZ-INT-001**（P0）聊天触发干预方案并保存到我的材料：发送轻症场景，如“刚吐完，嘴里发酸，喉咙不舒服，没有喝不进水/脱水/持续呕吐” → 等待 show_intervention_material 卡片 → 断言总览图、总时长、开始前确认、安全提示 → 点击“保存到我的材料” → 进入我的材料/我的跟练卡。
- **CX-BIZ-INT-002**（P1）开始跟练、步骤控制与进度持久化：在干预卡点击开始跟练 → 验证步骤图/步骤文本/倒计时 → 点击下一步/上一步/重播本步/返回总览 → 保存或产生 progress → 刷新会话或打开我的跟练卡详情。
- **CX-BIZ-INT-003**（P1）完成跟练后再跟练一次：使用短步骤素材完整走完所有步骤 → 进入 completed 状态 → 断言“已完成本轮跟练，可按需要再来一遍” → 点击“再跟练一次”。
- **CX-BIZ-INT-004**（P1）红旗/急症场景禁止展示干预卡：发送包含红旗信息的副作用问题，如持续呕吐、喝不进水、明显脱水或呼吸困难。
- **CX-BIZ-REPORT-001**（P0）报告图片解读后保存到健康档案：在聊天上传一张报告类医疗图片并发送“帮我解读” → 等待 medical_report_consultation_board 卡片/解析完成 → 出现“要保存这次图片吗？” → 点击保存 → 若未授权先同意健康档案授权 → 轮询保存任务或进入健康档案文档列表。
- **CX-BIZ-REPORT-002**（P1）报告图片保存暂不保存：报告图片解读成功后，在保存建议卡点击“暂不保存”。
- **CX-BIZ-REPORT-003**（P1）同一聊天图片保存任务去重：对同一 sessionId/sourceMessageId/documentHash 连续调用 save-from-chat-image 两次，或 UI 重复点击保存。
- **CX-BIZ-PROFILE-001**（P0）医疗字段审批同意后落库并在档案页可见：在聊天中明确说“我现在正在服用来曲唑，已经用了3个月” → 等待 update_structured_profile 产生确认卡片 → 如需授权先同意健康档案授权 → 在卡片点击同意 → 进入健康档案查看用药和时长。
- **CX-BIZ-PROFILE-002**（P1）审批拒绝后不落库且本会话不重复尝试：触发一个医疗字段审批卡 → 点击拒绝 → 再发送“刚才那个信息先不要更新”。
- **CX-BIZ-PROFILE-003**（P1）个人信息字段自动更新通知：用户在聊天中说“以后叫我小橙”或更正生日等 personal 字段 → 等待 profile_auto_updated 通知 → 进入个人信息页。
- **CX-BIZ-PROFILE-004**（P1）用药多药品时长编辑并保存：触发 medications 审批卡，含多个药品和默认/覆盖时长 → 在审批卡修改某药品时长 → 点击同意 → 打开健康档案。
- **CX-BIZ-OCR-001**（P0）上传病历图片、OCR、自动填充、保存档案：进入健康档案 → 上传病历 → 选择报告图片 → 开始识别 → 识别完成确认 → 回到列表 → 查看新增文档 → 核对病历档案中可识别字段 → 保存档案。
- **CX-BIZ-OCR-002**（P1）删除文档后刷新和旧详情不可访问：预置或上传一份病历文档 → 打开详情 → 删除并确认 → 刷新健康档案 → 尝试访问旧 docId 接口/详情。
- **CX-BIZ-OCR-003**（P1）历史病历文档读取并展示引用 chip：预置病历文档 → 在聊天问“请结合我最近上传的病理报告解释一下” → 等待 read_medical_documents 读取 d-1 → assistant 上方显示已查阅文档 chip → 点击 chip 打开图片。
- **CX-BIZ-MATERIALS-001**（P1）沟通卡和跟练卡双 Tab 管理：同一账号预置沟通卡和跟练卡 → 进入我的材料 → 在两个 Tab 间切换 → 分别进入详情 → 编辑沟通卡/继续跟练卡 → 返回列表 → 返回原会话。
- **CX-BIZ-SEC-001**（P1）清空健康档案后重建：专用账号准备结构化档案和病历文档 → 个人信息页进入账号与安全 → 清空健康档案 → 短信验证确认 → 进入健康档案确认空态 → 重新编辑档案并上传新文档。
- **CX-BIZ-SEC-002**（P1）注销进入冷静期并撤销恢复：专用账号进入账号与安全 → 注销账号 → 等待读秒 → 输入确认注销 → 短信验证 → 完成页退出登录 → 原手机号重新登录 → 进入冷静期页 → 点击撤销注销。
- **CX-BIZ-VOICE-001**（P1）语音输入识别、发送和回答播放：点击语音输入 → 授权麦克风 → 录音一段测试语音或注入音频 → ASR partial/final 进入输入框 → 发送 → AI 回复完成 → 开启 TTS 播放/停止。
- **CX-BIZ-ADMIN-001**（P2）新建干预素材并在聊天可触发：在 dev/localhost 打开素材上传台 → 新建测试素材，填写触发条件、总览图和步骤图 → 保存 → 可选同步/发布到当前环境 → 聊天发送命中场景。
- **CX-BIZ-PUSH-001**（P2）原生推送打开指定业务路由：登录后注入 cx-native-ready 和 push registrationChanged → 绑定设备 → 模拟 native push open 事件，route=/materials 或 /chat/:sessionId。
- **CX-BIZ-READ-001**（P1）字号设置影响聊天、沟通卡和跟练卡：进入阅读设置依次选择小/中/大 → 返回聊天查看消息字号 → 进入我的材料沟通卡详情和跟练卡详情查看字号。

## 明确不纳入“适合自动化全集”的情况
- 原始用例中标记为“半自动”或“接口/半自动”的失败注入、弱网、长等待、素材下线等场景未并入 CSV；若后续提供 Mock/测试钩子，可升级为自动化。
- LLM 相关闭环（沟通卡、干预卡、档案审批、历史资料读取）建议优先在测试环境增加“固定工具输出/agent harness”能力，否则真实模型存在不确定性，适合作为专项而非每次 smoke。

3. 新增代码功能时优先检查是否跨越 Chat 工具卡、保存到材料、健康档案授权/审批、外部页返回 session-events 这些闭环。
