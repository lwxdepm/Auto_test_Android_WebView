# WebView H5 功能自动化测试用例文档

- 更新时间：2026-05-06 22:34:20
- 适用范围：App WebView 套壳 H5 的登录、路由、聊天、健康档案、病历上传/OCR、材料、账号安全、阅读设置与 WebView 容器兼容性。
- 测试目标：验证 H5 在真实 WebView 容器中的用户路径、状态隔离、异常兜底与数据生命周期；不评估 AI 医学回答质量或 OCR 准确率。

## 代码阅读后的关键测试依据

- **验证码**：登录/清空档案/注销账号复用短信验证码服务，验证码 Redis TTL 为 300 秒，校验成功后立即删除；前端倒计时为 60 秒。
- **登录态**：token、consents、needsProfile 等存在 localStorage；401 会触发 logout 并清空跨 slice 状态，适合重点测切账号缓存隔离。
- **首次资料**：新账号 `requireCompleteProfile` 时不可跳过；`AuthGuard` 会把 needsProfile 用户强制带到 `/profile`。
- **健康档案**：进入 `/medical-records` 与保存医疗字段都需要 health_profile 授权；结构化档案是单档案 merge-patch，字段可见性由 currentConcern + gender 决定。
- **清空档案**：`purgeMedicalData` 只删除 `medical_records`、`medical_documents` 与 OSS 病历图片，不删除账号、个人信息、授权、对话与记忆；因此必须覆盖“删除后重建”。
- **聊天**：默认使用 fetch + ReadableStream 解析 POST SSE；特定 WebView 流式异常可经 `/client-error` 标记后降级到 `/chat/send-sync`。
- **上传/OCR**：前端单图限制 10MB、OCR 最多 10 张、聊天最多 5 张；后端还有全局 bodyLimit=10MB，需要单独测多图总请求体超限。
- **WebView 容器**：页面依赖 BrowserRouter、visualViewport、file chooser/capture、localStorage 与系统返回键策略；这些是套壳 App 自动化必须覆盖的容器能力。

## 测试账号与数据建议

| 账号类型 | 用途 | 要求 |
|---|---|---|
| A：正常账号 | P0 冒烟、聊天、导航 | 已完成个人信息，active，登录后进入 `/chat` |
| B：首次资料账号 | `/profile` 强制完善 | 新账号或后端返回 `needsProfile=true`、`requireCompleteProfile=true` |
| C：未授权健康档案账号 | 授权弹窗 | 无 health_profile consent |
| D：已有档案账号 | 健康档案编辑/删除/重建 | 已有结构化档案与至少一份病历文档，专用可清空 |
| E：男性/非肿瘤关注账号 | 字段可见性 | gender=男 或 currentConcern!=breast_tumor_care |
| F：材料账号 | `/materials` | 预置沟通卡；可选预置跟练卡 |
| G：冷静期账号 | 注销冷静期 | status=pending_deletion，专用账号 |
